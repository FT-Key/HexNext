## Decisiones tecnicas
- Admin en ruta `/admin` (no route group) para proteccion futura con middleware
- Formulario con react-hook-form + Zod (shared schema)
- Variantes se gestionan inline en el mismo formulario
- Imagenes: placeholder con URL por ahora (sin Cloudflare R2 en MVP)
- PrecioChanges log: se registra en console.log con estructura (placeholder para auditoria real)
- Mock repository guarda en memoria (no persistente, suficiente para MVP)

## AC cubiertos
- ✅ AC-1: Formulario con todos los campos del producto (sku, nombre, desc, marca, precio, etc.)
- ✅ AC-2: Gestión de variantes: AdminVariantManager permite agregar/quitar atributos de variante
- ✅ AC-3: Subida de imágenes: campo de URLs (placeholder, sin Cloudflare R2 en MVP)
- ✅ AC-4: Asignar a categoría (Select con categorías) y especificaciones técnicas (EspecsManager)
- ✅ AC-5: Los cambios de precio se registran en console.log con estructura (placeholder para auditoria real)

## Decisions
- Se usaron tipos planos (plain objects) para pasar datos de Server Components a Client Components
- `z.coerce.number()` con `as any` en resolver por incompatibilidad de tipos entre zod y react-hook-form
- UI components creados: form, select, textarea, badge, table, switch
